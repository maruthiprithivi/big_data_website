How should we rebuild the broken diagrams?

The current diagrams use position: absolute with hardcoded pixel offsets — that's why arrows break at different screen widths. Three options to fix it.

A

Flexbox/Grid layout — no coordinates

Rebuild architecture diagrams as CSS flex/grid layouts. Nodes are block elements; connectors are CSS borders, pseudo-elements (::before/::after), or short SVG overlays. Fully responsive — no pixel math.

Pros

  • No coordinate bugs — layout is flow-based
  • Works at any width, no scale hacks
  • Warm Notebook aesthetic fits naturally

Cons

  • Complex arrows (curves, fan-out) need SVG overlays
  • Limited to left-to-right or top-to-bottom flows
B

Inline SVG — explicit but correct coordinates

Draw each diagram as a self-contained SVG with viewBox. Coordinates are explicit but scale perfectly via width: 100% / height: auto. Best for MapReduce fan-out, Kafka partition diagrams, and any complex arrow routing.

Pros

  • Pixel-perfect arrows that scale correctly on all screens
  • Full control over curves, labels, animations
  • MapReduce fan-in/fan-out is trivial with SVG paths

Cons

  • More verbose to write and maintain
  • React state (hover, step animations) needs careful wiring
C

Keep ReactFlow — fix layout config

Keep ReactFlow (already installed) for all diagrams. Fix the broken ones by correcting the dagre layout configs. The existing "Which Architecture?" decision flowchart already works well with ReactFlow.

Pros

  • Consistent library across all diagrams
  • Auto-layout means no manual coordinates
  • Already works for the decision flowchart

Cons

  • Heavyweight for simple flow diagrams
  • ReactFlow's default style clashes with Warm Notebook palette
  • Harder to style to match the warm/calm aesthetic

I recommend A for simple flow diagrams (Lambda, Batch, Streaming) and B for complex fan-out diagrams (MapReduce, Kafka partitions, Spark DAGs). Keep ReactFlow only for the interactive decision flowchart where it already works.
